# Working in DataM8 CLI

Python 3.12+ backend for DataM8: Typer CLI, FastAPI HTTP server, Pydantic models,
connector plugins and Jinja2 generation. Use `uv`; the CLI entry point is `datam8.app:app`.

## Scope and contracts

- This repository owns generate/validate/index semantics and backend HTTP behavior.
  The frontend owns UI behavior; coordinate both only for a cross-repository feature.
- `datam8-model/` is the pinned schema submodule. Change schemas there first when
  model shapes change. `src/datam8_model/` is generated by `hatch_build_datamodel.py`;
  do not patch generated files as a substitute for a schema change.
- For HTTP or source import/refresh changes, consult and update the canonical
  [backend contract](docs/backend-contract.md) before changing behavior. Link to it
  from frontend docs instead of duplicating its text. Endpoints have no `/api` prefix;
  generation is synchronous, with no Jobs/SSE layer.
- Documentation changes run `node scripts/check-docs.mjs` with Node 24.
  Public user workflows belong in the central DataM8 handbook; keep API contracts here.
- For plugin work, use [connectors](docs/connectors.md). Preserve existing plugin
  hooks and distinguish regressions from incompatibilities already present on the base.
- For server startup/auth/CORS, use [server](docs/server.md). For test setup and
  fixture requirements, use [testing](tests/README.md). Read other docs as the task needs.

## Relevant entry points

- `src/datam8/cmd/`, `app.py`: CLI commands and registration.
- `src/datam8/api/`: app/server construction, routes and response envelopes.
- `src/datam8/source.py`, `plugins/base.py`, `plugins/manager.py`: source metadata,
  import/refresh and plugin loading.
- `src/datam8/model/`, `parser.py`, `factory.py`: wrappers, repositories, parsing and
  cached model/plugin access. Preserve local model edits and refresh factory state in tests.
- `src/datam8/generate.py`: ordered payload registration and template rendering.

## Local commands

```sh
git submodule update --init --recursive
uv sync --all-extras
uv run datam8 --help
uvx ruff check . --respect-gitignore --exclude datam8-model/
uvx --from ty==0.0.60 ty check src --exit-zero-on-warning
uv run pytest tests/test_015_source_mappings.py
uv run pytest tests --solution-path /path/to/disposable/Example.dm8s
uv build
```

The ty pin matches `.github/workflows/reusable-lint-build-test.yml`; keep them aligned.
`just check-format` modifies files and runs an unpinned type checker. Use the explicit
commands above when reproducing CI. Builds regenerate Python models; inspect the diff.

## Completion and boundaries

- Continue authorized local implementation, reproduction and targeted verification
  without asking for approval at each step. Ask when a missing decision materially
  changes scope or externally visible behavior; honor explicit plan/approval gates.
- Use disposable fixtures or copies for import/save/generate tests. Do not use a
  customer solution as a committed test dependency or contact its live services merely
  to run local regression tests. The existing full suite requires a solution fixture.
- Add regression coverage for changed behavior, including unchanged legacy plugin
  behavior. For HTTP changes, exercise requests and returned/persisted state. A feature
  spanning UI and backend needs at least one UI-to-backend completion test.
- Run relevant checks, fix failures caused by the change, then stop repeating passing
  checks unless another edit or unresolved concern warrants it.
- Report findings with trigger, impact and code location; distinguish tested results,
  skips and limitations. Do not claim customer compatibility from mocks alone.
- Publishing, pushing, merging and customer-data changes follow the user's authorized
  scope. Keep unrelated local work intact.
