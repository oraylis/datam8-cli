# DataM8 CLI 2.1.1

This patch release fixes entity description refresh and centralizes model and folder
entity ID allocation in the backend.

## Entity description refresh

- Complete refresh updates the entity description, including clearing a removed
  description. Sources-only refresh and entities without external sources retain
  their existing description. Multiple sources may supply the same description;
  conflicting descriptions are rejected instead of selecting one arbitrarily.

## Backend-assigned entity IDs

- New model and folder entities receive random numeric IDs in the JavaScript-safe
  range from one backend allocator. Create, clone, source import, migration and
  implicit folders avoid IDs already used by either entity type.
- Existing valid IDs remain unchanged on update, rename and move. Loading and
  saving reject IDs outside the supported range and duplicates within each entity
  type, with the affected locators in the error. Historical overlap between model
  and folder IDs remains supported.
- Create ignores supplied IDs; clients must use the returned entity ID. Multiple
  creates continue to use the existing entity endpoint followed by one model save.

## Other changes since 2.1.0

- Include the dependency and schema security corrections already merged into main,
  and avoid logging secret references and registry contents.
- Clarify installation from prebuilt release packages.

## Compatibility and release

The solution schema version remains **2.0.0**. Existing plugin hooks and source
location handling are unchanged. Use the updated backend package or submodule
revision to receive these changes. Clients creating model or folder entities must
retain the IDs returned by the backend. Existing solutions with duplicate or
out-of-range IDs must be corrected before they can be loaded or saved; valid
existing IDs are not renumbered.

After merging the release PR into main, push the protected tag `v2.1.1` at the merged
commit. The release workflow verifies the version, runs CI and publishes the tested
wheel and source archive to GitHub Releases. It does not publish to PyPI.

See the [backend contract](../backend-contract.md) and [release process](../ci.md).
